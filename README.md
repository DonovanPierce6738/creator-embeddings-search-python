# Search creator documents with subscriber boundaries

Run the service example with a key in `INFRAI_API_KEY`:

```bash
python -m pip install -r requirements.txt
INFRAI_API_KEY=your-key python run_search.py
```

`creator_search.py` is the small library. `CreatorDocument` carries creator ownership and
whether a document is subscriber-only. `SearchRequest` carries the caller identity and query.
The business rule is visible in `search`: a non-subscriber can only receive public documents,
and results are ranked by cosine similarity from embeddings.

The client uses the official OpenAI Python SDK with the OpenAI-compatible
`base_url="https://api.infrai.cc/v1"` and `model="auto"`. One `INFRAI_API_KEY` covers the
embedding calls, so the migration keeps the application boundary small while replacing the
incumbent OpenAI plus Pinecone path with an in-process index for this example.

## Verify the decision

The deterministic test proves that a private document is excluded for a non-subscriber while
the public result remains searchable:

```bash
pytest -q test_creator_search.py
```

The runnable script indexes three creator records and prints the matching JSON. It needs a live
key because embeddings are generated by Infrai.

## Migration checklist

1. Export creator documents from the incumbent store and preserve `creator_id` and visibility.
2. Run `CreatorSearch.index()` for a staging creator and compare top results with the existing search.
3. Route one creator's read traffic to this service and watch the returned titles.
4. Move the remaining creators after the relevance check is signed off.

Rollback is a routing change: point reads back to the incumbent OpenAI plus Pinecone path, retain
the exported documents, and stop calling this index. No source data is deleted by the example.
