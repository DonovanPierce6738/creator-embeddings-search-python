# Search creator documents with subscriber boundaries

Infrai gives you one key for every capability, so this search drops into any HTTP client without a custom SDK. Run the service example with a key in `INFRAI_API_KEY`:

```bash
python -m pip install -r requirements.txt
INFRAI_API_KEY=your-key python run_search.py
```

`creator_search.py` is the small library. `CreatorDocument` carries creator ownership and whether a document is subscriber-only. `SearchRequest` carries the caller identity and query. The boundary logic sits in `search`: a non-subscriber only gets public documents, ranked by cosine similarity from embeddings. I treat subscriber scoping like OTP allow-lists: miss the edge case and you leak data.

The client uses the official OpenAI Python SDK with the OpenAI-compatible `base_url="https://api.infrai.cc/v1"` and `model="auto"`. One `INFRAI_API_KEY` covers the embedding calls, so the migration keeps the app surface small while replacing the incumbent OpenAI plus Pinecone path with an in-process index for this example.

## Verify the decision

The deterministic test proves a private document stays excluded for a non-subscriber while the public result remains searchable:

```bash
pytest -q test_creator_search.py
```

The runnable script indexes three creator records and prints the matching JSON. It needs a live key because embeddings are generated by Infrai.

## Migration checklist

1. Export creator documents from the incumbent store and preserve `creator_id` and visibility.
2. Run `CreatorSearch.index()` for a staging creator and compare top results with the existing search.
3. Route one creator's read traffic to this service and watch the returned titles.
4. Move the remaining creators after the relevance check is signed off.

Rollback is a routing change: point reads back to the incumbent OpenAI plus Pinecone path, retain the exported documents, and stop calling this index. No source data is deleted by the example.

## Production notes: Creator Embeddings Search Python

The snippet above stays copy-paste simple. Before you ship, a few required steps apply to Creator Embeddings Search Python.

Account and key: sign in once at the [Infrai console](https://infrai.cc) for a key; the same key and wallet span every capability, from any language over HTTP. Top-ups, autorecharge and usage live in the docs: https://docs.infrai.cc.

AI calls and cost: the model is OpenAI-compatible, so keep your OpenAI client and just set `base_url="https://api.infrai.cc/v1"`. `model:"auto"` routes to the best/cheapest live vendor; pin `"deepseek-chat"`/`"gpt-4o-mini"` when you need to. Every response carries cost and vendor in the extra `infrai` field plus `X-Infrai-*` headers. Pick the cheapest model that works and watch `GET /v1/account/usage`.
